# P1-09 part E — year-end closing

## Shipped

- `modules/year-end`: preview, prepare, approve, reverse, discard; `YearEndClosing` model
  (migration `20260907100000_year_end_closing`, RLS, audited); permission module `year-end`
  (view / prepare / approve) wired into the Accounts, Auditor and Owner default roles and the
  `accounts` feature.
- Approval posts the closing JV on the year's last day (`refDocType YEAR_END`), closes the year's
  periods, opens the next year's period and head-office numbering series, moves the freeze date to
  the year end and rolls the invoice-settings FY forward. Reversal cancels the JV with a reversal
  once the freeze date has been moved back.
- System ledger `EQ-002 Retained Earnings` (Reserves & Surplus). The P&L statement excludes
  `YEAR_END` vouchers; the trial balance and balance sheet include them.
- Web `/accounts/year-end` "Year-End Closing" with the freeze-date control; smoke covered.
- 4 integration tests; routes and leak snapshots updated.

## Half-done / known gaps

- Four-eyes is by permission only (prepare vs approve); the same user holding both can do both.
  P1-04 (PC7 `FilingApproval`) should wrap approve so preparer ≠ approver is enforced there.
- Reversal leaves the year's periods closed and does not touch the next year's sequences; reopen
  periods from the period-control API (or the year-end screen once it grows a periods table).
- Opening balances carry through the continuous ledger (no opening-balance vouchers are cut for
  the new year); Tally-style "carry forward" rows are P1-06 (Tally export) territory.
- Branch (business-place) numbering series for the new year are created lazily on first use,
  not at closing.
- No web link from the closing row to its voucher yet.
