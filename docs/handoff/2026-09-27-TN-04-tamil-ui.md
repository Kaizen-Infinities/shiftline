# TN-04 — Tamil UI (தமிழ்) for shop-floor and store screens

Spec: `docs/research/tamil-nadu/market-and-features.md`, "(d) Prioritised feature list", item 4.

## Shipped

- **Schema**: `User.locale` (`VARCHAR(5)`, default `'en'`) with a `CHECK (locale IN ('en','ta'))`.
  Migration `20260927010000_user_locale` (column only; `users` already has RLS and its audit
  trigger). Drift check clean.
- **Shared**: `packages/shared/src/locales.ts` (`SUPPORTED_LOCALES`, `Locale`, `isLocale`,
  `toLocale`) and `API_PATHS.user.myLocale`.
- **API**: `PATCH /api/users/me/locale` (`authMiddleware` + strict zod body `{ locale: "en" | "ta" }`;
  the target is always the token's user, a `userId` in the body is a 400, platform admins get 403).
  It returns the updated profile. `locale` is now in the login response, `GET /api/auth/me` and
  `GET /api/users/profile` (admins always `en`). No permission key: like `/users/profile`, every
  signed-in user may set their own language (operators often hold no `profile.*` permission).
- **Web i18n** (`apps/web/src/i18n`, no new dependency): `en.ts` is the typed source of keys
  (~770 keys); `ta.ts` is typed `Messages`, so a missing or extra key fails `tsc`. `translate.ts`
  falls back to English for a blank/missing value, fills `{placeholders}` and prints numbers with
  `en-IN` digits. `I18nProvider` (in `main.tsx`) reads `auth.user.locale` (before sign-in: the last
  choice on this browser), sets `<html lang>`, and injects Noto Sans Tamil from Google Fonts only
  for Tamil; CSS falls back Inter → Noto Sans Tamil so digits and Latin stay in Inter. `useT()`
  gives `t`, `tDynamic`, `locale`, `setLocale` (optimistic, rolled back on error).
- **Nav**: `nav.config.ts` is unchanged; keys derive from ids (`nav.area.<id>`, `nav.screen.<id>`,
  `nav.group.<area>.<group>`, `nav.link.<area>.<path>`, `nav.action.<path>`, `nav.crumb.<segment>`)
  through `i18n/navI18n.ts`, applied in `useNav` (sidebar, hubs, mobile tab bar, command palette,
  breadcrumbs). The English title is added to keywords so "GRN" still finds the screen in Tamil.
  Home/operate/people areas are translated fully; money/admin areas show a Tamil area name with
  English screens.
- **Language switch** (English / தமிழ்): account menu of the new shell, profile page
  ("Preferences"), and the login page (guest, browser-only).
- **Translated screens**: shell (top bar, sidebar, tab bar, notifications, sign-out dialog), hub
  page, login, profile, shift execution console, hourly production entry, goods dispatch (list,
  create, view/gate/store parts), GRN list and GRN receive form (goods fields; TDS, payment and
  discount stay English), raw-material stock, day-end stock. `StatusBadge` gained an opt-in
  `translate` prop (shop-floor/store screens only). Stored reason values stay English (reports
  group by them); only labels translate.
- **Tests**: `apps/api/test/integration/user-locale.spec.ts` (default, set/unset, login/profile
  carry it, 5 validation rejections, 401, cannot change another user, admin 403, foreign tenant sees
  nothing); `apps/web/src/i18n/i18n.spec.ts` (same keys, no empty values, same placeholders, Tamil
  script, fallback, nav keys match `nav.config` titles). e2e: `/shift-execution` and
  `/inventory/eod-stock` smoke lines, a language-switch test; `/company/view` marker is now
  case-insensitive ("Employee code").

## Cut / later

- Other shop-floor screens (production orders, daily planning, wastage, finished-goods stock, stock
  adjustments, machines) and the command palette's own chrome are still English.
- Hourly work report list/edit pages, dispatch gate/store approval page headers.
- Server error messages stay English (they are shown as-is).
- A native Tamil reviewer should read `ta.ts` once before a customer demo.

## Changelog

Operators and store keepers can now switch Shiftline to Tamil (தமிழ்) from their profile menu,
and the menus, shift console, hourly entry, dispatch, GRN and stock screens appear in Tamil.
