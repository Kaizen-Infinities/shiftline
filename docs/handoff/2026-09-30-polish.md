# Polish pass — reachable actions, in-app confirms, labelled controls

**Changelog:** On phones the Save button on forms is no longer hidden behind the bottom bar,
confirmations open inside the app instead of as browser pop-ups, and every filter and input can
be read out by a screen reader.

Commit `08f0697` plus this note. Visual and accessibility only, apart from three client fixes to
failing API calls listed below. No API, permission or schema change.

## How it was found

One scripted pass over all 161 static routes at 1440 × 900 and 390 × 844 (touch), signed in as
the demo owner. It checked API errors, console errors, horizontal scroll, the h1, unnamed and
unlabelled controls, touch targets, text under 11 px, clipped labels and junk text
(`undefined`, `NaN`). Screenshots of the key screens were reviewed by eye. The changed screens
were re-scanned afterwards.

## Fixed

- **Sticky form footers** (`.sl-sticky-footer`, `assets/css/style.css`) sit above the phone tab bar
  while it is on screen. The tab bar is `fixed`, so the old `sticky bottom-3` put the primary
  Save under it on every create/edit form. Used by `FormFooter` (sales `tradeUi`, stock),
  `StickyFormFooter` (production), and the hand-built footers on the employee, shift, expense,
  company, WhatsApp, payroll settings and accounts forms. A footer that sat flush to the bottom
  sets `[--sl-footer-gap:0px]`. Do not put `sticky bottom-*` utilities on a new form footer.
- **Dashboard quick actions** are in aligned columns (2 / 3 / 6), so the sixth action no longer
  wraps onto a row of its own.
- **`ConfirmDialog` / `useConfirm`** (`components/ui/v2`) replaces `window.confirm` on tenant
  device revoke, payroll slabs and components, the negative-balance payment voucher, and year-end
  approval. It is an alertdialog with a focus trap, closes on Escape and restores focus. The
  older declarative `CommonConfirmModal` (~30 call sites) is untouched.
- **Accessible names** on about 40 filters, search boxes and line-item inputs (reports,
  payable and receivable, vouchers, year-end, e-invoice, machine gateways, SMS, inventory lists,
  sales documents, payroll run). The shared `SelectInput`, `DatePickerCalendar`,
  `AutocompleteInput` and `LedgerSearchInput` take an `ariaLabel` prop.
- **Text under 11 px** raised to 11 px: attendance grid, payroll run, role permissions,
  compliance calendar, dashboard chart axes.
- **Off-system UI:** Bootstrap classes on expenses and the shift-records modal, and raw palette
  colours on machine assignments, are now UI v2 tokens. Socket connection logs are dev-only
  `console.debug`.
- **Failing calls:**
  - Customer dropdowns clamp `limit` to the API's 200. It was a 400 on eight sales and
    receivable screens.
  - The store form no longer calls `/api/store-types`, which does not exist (404).
  - A failed list load no longer leaves an unhandled rejection (`useListCache`).

## Checked

Typecheck and lint are clean (0 errors). `e2e/smoke.spec.ts` and `e2e/platform.spec.ts` pass,
59/59.

## Open: bugs found, not fixed here

- **Bank reconciliation fails for every tenant.** `BankReconciliationPage` fills its picker
  from `GET /api/accounts/bank-accounts`. That endpoint returns cash and bank _ledgers_ with
  integer ids, "Cash in Hand" among them. `/api/banking/*` validates `bankAccountId` as a
  `BankAccount` uuid, so every call is a 400. No endpoint lists `BankAccount` rows (only
  onboarding reads them). The fix is a tenant-scoped `GET /api/banking/accounts` (`banking.view`)
  with integration and cross-tenant tests; the page then uses it.
- **Sales, purchase and inventory reports return 403 for everyone.**
  `apps/api/src/modules/reports/reports.routes.ts:14–54` require `reports.view`, which is not in
  the shared permission registry. The nav gates on `sales-reports.view`, `purchase-reports.view`
  and `inventory-reports.view`. This is an auth change and needs the named human approver.
- **Customer dropdowns** show at most 200 customers. A tenant with more needs a searchable,
  server-side picker.
- **Line-item inputs** on the sales documents are 16–31 px tall on phones, under the 40 px target.
- **Page titles** mix Title Case and sentence case, some carry "Management" or "List", and the
  profile page says "Hello DEMO Owner". Normalising them changes copy, so the owner has to agree.
- `react-country-state-city` fetches its state list from a CDN at runtime. That fails offline and
  in this sandbox.
