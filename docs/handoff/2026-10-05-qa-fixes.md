## Live demo tenant

The seed fixes only reach the live tenant through a reseed (the `demo-seed` job). The reseed only
adds rows; it does not delete or rewrite the QA records.

- The 14 old Ready For Planning production orders stay. The ten `MO-DEMO-*` orders are added beside
  them; delete or cancel the old ones in the app if the board should be clean.
- Demo employees without a role: the reseed gives them the Production role (and department if empty).
- Old products: the reseed sets `productType` to `SALES_PRODUCTION` on P001-P005 where it is still
  the legacy `PRODUCTION`, and fills the HSN where it is empty. Before this note the repair only ran
  when the HSN was empty, so a product with an HSN and the old type was left alone; it now repairs the
  two fields separately. Products the owner created are not touched.
- Minimum stock is set only where it is still 0, so a level a user chose is kept.
- Machine assignments and weekly programs made on Sunday-based weeks (for example 4-10 Oct) need
  re-editing; they are not migrated.
- Deploy order, per `docs/runbooks/hosting.md`: `backup`, then `update`, then run the `demo-seed` job.
  Do the security-fix reconciliation queries in the 2026-10-04 note first.

## Numbering notes for the next developer

- `documentNumberService.peek()` never inserts, locks or consumes. `takeShownOrNext()` is for forms
  that submit the number they were shown: one conditional UPDATE advances the series only if the
  shown number is still next, otherwise the save gets a fresh `next()` number. It runs inside the save
  transaction, so a failed save does not burn a number.
- The production order screen creates the first line first and numbers the other lines from the
  number the server returned.
- Legacy production order codes (for example `PO-2609-014`) are kept as they are.
