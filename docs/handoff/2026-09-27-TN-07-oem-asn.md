# TN-07 — OEM ASN, packing labels and part-number cross-reference

Spec: `docs/research/tamil-nadu/market-and-features.md`, "(d) Prioritised feature list", item 7.
Builds on TN-02 (`modules/delivery-schedules`).

**Changelog:** Raise an ASN for your OEM customer straight from the sales invoice, with their part
numbers and standard packs filled in, export it for the portal, print a QR label for every pack,
and have the dispatch count toward your schedule adherence automatically.

## Shipped

- **Schema** (migration `20260927030000_oem_asn`, RLS `tenant_isolation` / `platform_bypass`,
  audit triggers; all three models in `AUDITED_MODELS`):
  - `CustomerPartMap`: customer + product → `customerPartNo`, description, `packQty` (std pack),
    `packType`, `isActive`; `@@unique([companyId, customerId, customerPartNo])` (the service also
    refuses a case-insensitive clash).
  - `Asn`: `asnNo` `@@unique([companyId, asnNo])`, customer, FK `SalesInvoice` (checked with
    `findFirst`), invoice no/date snapshot, vehicle, transporter, LR no/date, `dispatchAt`
    (Timestamptz), status `DRAFT → SENT → ACKNOWLEDGED`, `DRAFT|SENT → CANCELLED` (reason kept).
  - `AsnLine`: product, `customerPartNo`, qty, `packQty`, `packs`, optional `scheduleLineId`
    (TN-02 `CustomerScheduleLine`, SetNull) and `dispatchId` (the TN-02 dispatch it booked).
- **Adherence link**: marking an ASN SENT books one `CustomerScheduleDispatch` per schedule-linked
  line (dated the India day of `dispatchAt`, with invoice and ASN number), the same row TN-02's
  manual entry writes; cancelling a sent ASN deletes them again. TN-02's line delete now refuses
  (409 `LINE_ON_ASN`) while a live ASN points at the line.
- **Pure calc** `asn.calc.ts` (integer thousandths): `splitPacks`, `packsFor`, `buildLabels`
  (pack sequence runs across the ASN; QR = `asnNo|partNo|qty|packSeq`), `allocateToSchedule`
  (earliest open line first, excess returned unlinked), transitions, vehicle-number normalising.
- **API** `/api/asn` (`authMiddleware`, `requireFeature("sales")`, `asn.view|create|edit|export`):
  part-map `GET/POST /part-maps`, `PATCH/DELETE /part-maps/:id`; `GET /invoices` (invoices with no
  live ASN), `GET /prefill?salesInvoiceId` (lines from invoice items + part map, split over open
  schedule lines net of draft ASNs; vehicle/LR from the invoice's live e-way bill),
  `GET /`, `POST /` (lines optional: omitted = prefill; 400 `PART_NOT_MAPPED` if any product has
  no mapping), `GET|PATCH /:id` (draft only), `POST /:id/status`, `GET /export-formats`,
  `GET /:id/export?format=`, `GET /:id/labels?size=A4|100X150` (PDF). One live ASN per invoice;
  default number `ASN-<invoiceNo>` (`-R1`… after a cancelled one). No DELETE.
- **Export providers** `modules/asn/providers/`: `AsnExportProvider`, `GENERIC_CSV` (BOM, RFC
  4180, formula-injection guard). No xlsx library in the repo, so no GENERIC_XLSX. Documented
  TODO adapters (listed as unavailable, 501 on use): EDIFACT DESADV, ANSI X12 856, Hyundai,
  Ashok Leyland, TVS Motor, Royal Enfield, Renault Nissan, Daimler India portals. Each needs the
  OEM's real upload template; none is guessed.
- **Labels**: `asn.labels.ts`, inline-SVG QR (`qrcode`, already a dependency) rendered through the
  shared puppeteer helper; `pdfGenerator.ts` gained optional `page` size and `margin` (defaults
  unchanged). A4 = 8 labels of 99 × 67 mm; thermal = one 100 × 150 mm label per page.
- **Registries**: permission module `asn` (view/create/edit/export), `sales` feature, STORES
  role on provisioning, `API_PATHS.asn`.
- **Web**: `/sales/asn` (`AsnPage.tsx`: status chip tabs, search, list + detail, create-from-
  invoice flow with editable part no / qty / std pack / schedule line, mark sent / acknowledged
  with OEM ref / cancel with reason, export, print labels A4 or thermal) and
  `/sales/customer-part-numbers` (`CustomerPartMapPage.tsx`: inline table editing that saves on
  blur, add row, active toggle, remove). Nav entries under Sales → Delivery, an "ASN" hub chip,
  smoke lines, nav spec updated.
- **Tests**: `test/unit/asn-calc.spec.ts` (14), `test/integration/asn.spec.ts` (11: part-map CRUD
  and every rejection, prefill split, create + 409 second ASN, draft edit, SENT booking TN-02
  dispatches, ACK, cancel removing them, CSV / 400 / 501 export, both label PDFs, every create /
  update / status rejection, 403 for accounts, foreign company sees nothing and its invoice,
  customer and schedule line are refused). Leak and routes snapshots updated.

## Checked on the running stack

Own API (:5207, `tn07_dev`) + vite (:5187): list, detail, invoice picker, create form and the
part-map screen at 1440 light and 390 dark; the label HTML rendered at A4 and 100 × 150.

## Not done / next

- OEM-specific export formats (need real templates from a customer); no XLSX (no library).
- No EDI/portal transmission: "Sent" is set by the user after uploading.
- Lines cannot be added to a draft from the web beyond the prefill (the API's `PATCH /:id`
  replaces lines); an unmapped item must be mapped or removed before creating.
- Labels are not reprintable per single pack (whole ASN only); no GS1 / barcode-128 option.
