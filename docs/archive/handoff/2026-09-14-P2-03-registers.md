# P2-03 — The inspector's registers

## Shipped

- New read-only module `apps/api/src/modules/registers/` (`registers.routes.ts`,
  `registers.service.ts`, `registers.validation.ts`, `registers.export.ts`), mounted at
  `/api/registers`, gated by `authMiddleware` and the new `registers.view` / `registers.export`
  permission keys (feature `payroll`; owner and the auditor role hold them — the only seeded
  roles that read payroll today).
- Six registers, all computed from persisted data, never from payroll logic:
  - `GET /muster-roll?month=` — one row per active employee, one column per day (P/A/H/L/WO plus
    per-day OT hours) and totals, from `AttendanceRecord`.
  - `GET /wages?month=` — days worked, rate, basic, allowances, OT wages, gross, PF/ESI/PT,
    fines, advances recovered, other deductions, net, mode and payment date, from `PayrollResult`
    (basic/allowances from `EmployeePayrollConfig`, since a run doesn't snapshot them).
  - `GET /overtime?month=` — OT hours, normal and double OT rate, OT wages, and cumulative
    quarter hours against the 125-hour cap, reusing `OVERTIME_MULTIPLIER` and
    `QUARTERLY_OVERTIME_CAP` from `labour.calc.ts` (read, not modified).
  - `GET /fines?from&to` and `GET /deductions?from&to` — dated entries from the new
    `EmployeeFineDeduction` model; fines carry a per-employee-per-month 3% wage ceiling check
    (Payment of Wages Act s.8) that reports a breach without blocking anything.
  - `GET /advances?from&to` — date, amount, purpose, recovered to date, balance, from
    `SalaryAdvance`.
  - Every register serves `?format=csv` (header row, escaped) and `?format=pdf` (rendered via
    the existing `generatePdfFromHtml` puppeteer helper already used by sales/purchase
    documents — no new PDF dependency).
- Schema: `EmployeeFineDeduction` (migration `20260914030000_registers`, RLS, not audited —
  matching its siblings `SalaryAdvance` and `EmployeePermanentDeduction`), holding a dated fine
  or damage/loss deduction with cause, amount and a persisted `shownCauseGiven` flag.
- Permissions/features/api-paths: `registers.{view,export}` in `permissions.ts`, `registers`
  module added to the `payroll` feature, `API_PATHS.registers` block, and the `AUDITOR` role in
  `provisioning.service.ts` picked up both keys.
- Web `/hr/registers` (`apps/web/src/modules/payroll/pages/RegistersPage.tsx`,
  `apps/web/src/services/registersService.ts`): register selector, month or date-range filter, an
  optional business-place filter, the table per register, and Export CSV/PDF buttons. Sidebar
  entry under Payroll; smoke coverage in `e2e/smoke.spec.ts`.
- Test factories (`createEmployee`, `createAttendanceRecord`, `createPayrollRun`,
  `createPayrollResult`, `createSalaryAdvance`, `createFineDeduction`) and
  `apps/api/test/integration/registers.spec.ts` (10 tests): each register's rows and totals from
  factory data, CSV header row, month/range validation rejections, permission refusal, and a
  cross-tenant test that a second tenant's employee never appears (plus the automatic sweep in
  `leak.spec.ts`, which required no special-casing since these routes take no path params).

## Decisions worth knowing

- **`EmployeeFineDeduction` is a new table, not a column on an existing one.** The spec assumed
  a fines/deductions model already existed to add a "shown cause" column to; none does — the
  closest, `EmployeePermanentDeduction`, is a recurring payroll-run deduction (loan EMI, etc.),
  not a dated incident with a cause. Kept apart deliberately.
- **Nothing writes to `EmployeeFineDeduction` yet.** The module is read-only by scope, and no
  other module raises a fine or a deduction today (advances already have a creator in the
  payroll module). The registers will be empty in the running app until that's built — the
  integration tests populate rows directly, the way the demo seed will once a source exists.
- **`businessPlaceId` is accepted and validated, not applied.** Neither `Employee` nor
  `AttendanceRecord` carries a business-place link in the schema. The filter validates the id
  belongs to the tenant (400 otherwise) so it fails loudly rather than being silently ignored,
  but every register currently reports all business places together.
- **Wages register TDS column is 0.** P2-02 (payroll reconciliation, built in parallel) is
  adding salary TDS to the payroll run; no field exists yet to read. Once it lands, `wages()` in
  `registers.service.ts` should read it instead of hardcoding 0.
- **Basic/allowances in the wages register are the current `EmployeePayrollConfig`, not a
  point-in-time snapshot.** `PayrollResult` doesn't persist the basic/DA/HRA split per run, so a
  later change to an employee's config will retroactively change what an old wages register
  shows for basic and allowances (gross, PF, ESI, net are all correctly point-in-time from
  `PayrollResult` itself).
- **Half day and holiday share the "H" muster-roll letter**, matching the spec's six-symbol
  alphabet (P/A/H/L/WO/OT). Internally the two are tallied separately in the response's `totals`
  (`halfDay` only counts `HALF_DAY`; holidays aren't broken out as their own total field since
  the spec doesn't ask for one) — worth revisiting if the inspector's form wants them apart.

## Half-done / known gaps

- No screen or endpoint records a fine, a deduction, or a "shown cause" notice — see above.
- `businessPlaceId` filtering (see above) — needs a real link on `Employee`/`AttendanceRecord`
  before it can filter anything, which is a schema change outside this package's scope.
- The muster-roll PDF can get wide for a 31-day month; `generatePdfFromHtml` renders portrait
  A4 with fixed margins and isn't parameterised for landscape. Small font (11px) keeps it
  readable for now; a landscape option on the shared helper would help every module that emits a
  wide table, not just this one.
- Overtime register's "normal rate" falls back to the current `EmployeePayrollConfig` when no
  payroll run exists for the month (e.g. computed before the run). Once a run exists it uses the
  persisted `dailyRate`, which is correct; before that it's an estimate.
- Salary TDS in the wages register — see above, blocked on P2-02.

## Blocked on you

- Whether fines/deductions get their own data-entry screen (and if so, which role may record
  one) is a product decision outside this package's scope; the register exists either way.

## Changelog sentence

The muster roll, register of wages, register of overtime, register of fines, register of
deductions and register of advances the labour inspector asks for are now available at
`/hr/registers`, each exportable as CSV or PDF.
